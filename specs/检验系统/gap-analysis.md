## 实施步骤

### Step 1: 检验核心数据表映射（阻塞所有后续）

三张核心表目前零代码，必须先打通。

| # | 任务 | 技术要点 |
|---|------|----------|
| S1-1 | LisInspectionSample Entity（95 字段） | inspection_id 无自增 PK，需手动生成雪花 ID |
| S1-2 | LisInspectionSample BO/VO/Mapper/Service/Controller | 标准 CRUD + 状态流转方法（sign/receive/reject） |
| S1-3 | LisInspectionResult Entity | 联合主键 (inspection_id, test_item_id) |
| S1-4 | LisInspectionResult BO/VO/Mapper/Service/Controller | 批量保存结果、按检验单查询 |
| S1-5 | LisInspectionReport Entity | report_id + report_format + report_file |
| S1-6 | LisInspectionReport BO/VO/Mapper/Service/Controller | 报告生成 + PDF 导出 |
| S1-7 | LisChangeLog Entity/Mapper/Service | 审核留痕依赖 |

### Step 2: 标本管理（检验入口）

| # | 任务 | 说明 |
|---|------|------|
| S2-1 | 样本状态枚举 + 状态机 | PENDING->RECEIVED->CHECKED->TESTING->COMPLETED->REVIEWED->PUBLISHED |
| S2-2 | 后端: 签收/核收/拒收接口 | 状态校验 + lis_change_log 记录 |
| S2-3 | 前端: 标本接收页面 | 列表 + 签收/核收/拒收 + 条码扫描输入 |
| S2-4 | 前端: 标本详情页 | 患者信息 + 检验项目 + 状态流转时间线 |

### Step 3: 结果录入

| # | 任务 | 说明 |
|---|------|------|
| S3-1 | 后端: 结果批量保存 | 一个检验单对应多个 lis_inspection_result 行 |
| S3-2 | 前端: 结果录入页面 | 检验单详情 + 项目结果表格（定量/定性）+ 参考范围自动匹配 |
| S3-3 | 异常结果标识 | 超出参考范围标红，危急值标红+图标 |

### Step 4: 报告生成与审核

| # | 任务 | 说明 |
|---|------|------|
| S4-1 | 后端: 报告生成 | 从 sample + result 组装数据，填充 HTML 模板，PDF 导出 |
| S4-2 | 后端: 审核接口 | 通过/驳回/撤回，驳回原因必填，lis_change_log 留痕 |
| S4-3 | 后端: 报告版本管理 | 修改后生成新版本，保留历史 |
| S4-4 | 前端: 报告预览页面 | HTML 模板渲染 + 异常高亮 + 审核信息 |
| S4-5 | 前端: 审核工作台 | 待审列表 + 通过/驳回操作 |
| S4-6 | 前端: 报告查询页面 | 多维度筛选 + Excel 导出 |

### Step 5: 危急值管理

| # | 任务 | 说明 |
|---|------|------|
| S5-1 | 后端: 危急值检测 | 结果保存时对比阈值，标记 police_state |
| S5-2 | 后端: 报警推送 | WebSocket + 站内消息 |
| S5-3 | 前端: 危急值弹窗 + 处理页 | 弹窗报警 + 闭环记录（上报/接收/处理/反馈） |

### Step 6: 流程监控

| # | 任务 | 说明 |
|---|------|------|
| S6-1 | 后端: 状态统计+超时检测 | 按科室/时间聚合，超时预警 |
| S6-2 | 前端: 流程监控看板 | 状态分布可视化 + 超时预警列表 |

## 依赖关系

```
S1 (核心表映射)
 ├─→ S2 (标本管理)
 │    └─→ S6 (流程监控，依赖 S2 状态)
 ├─→ S3 (结果录入)
 │    └─→ S5 (危急值，结果保存时触发)
 └─→ S4 (报告+审核，依赖 S1+S3)
```

**并行机会**: S2 + S3 可在 S1 完成后并行，S4/S5/S6 后续跟进。
